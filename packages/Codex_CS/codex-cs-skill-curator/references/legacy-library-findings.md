# 现有 Codex_CS Skill 库提炼结果

本模板依据旧库中的城市宣传片、地产建筑、巨型 IP、巨型 3D Logo、建筑拆解组装和晨曦云雾航拍等 Skill 提炼。这里记录设计依据，不作为任何具体业务 Skill 的创作规则。

## 共同能力

旧 Skill 反复出现以下可复用知识类别：

- 素材角色：身份、场景、风格、首帧、尾帧、参考视频、音乐和声音。
- 素材关系：编号、顺序、必选性、可变数量和时间对应关系。
- 视觉创作：主体一致性、环境、构图、材质、光照、色彩和空间尺度。
- 运动设计：摄影机运动、主体动作、物理交互和状态变化。
- 时间设计：逐镜时段、节奏权重、转场、开头和结尾条件。
- 质量经验：常见失败、规避方式、正反例和社区实践。

因此标准包必须同时支持确定性契约和渐进加载的创作知识，不能只用一个长 Markdown 文件承载全部内容。

## 发现的历史问题

### 非标准文件格式

旧资料存在平铺 `.md`、标题式 name/description、导出包装文本和超过 500 行的单文件。标准包改用严格 frontmatter 和一层 `references/`，以降低触发时上下文成本。

### 重复与版本并存

旧库中存在内容完全相同的平铺文件与标准目录包。新标准以 `skill_id`、来源哈希、包哈希和发布凭证阻止重复入库。

### 正则推断契约会误判

建筑拆解组装资料明确需要多张参考图，却因自然语言格式未被旧解析器识别，最终被错误归为无素材视频。新标准要求人工审核后的显式 `contract.json`，不再从正文临时猜测关键执行事实。

### 示例污染契约

旧资料中的后续示例可能再次出现“图片1、图片2”或具体城市、人物和项目。新标准把示例单独保存，并明确禁止它参与素材契约推导。

### 强制规则与经验混合

旧资料常将平台经验、作者偏好、社区反馈和真正的素材要求混写为“必须”。新标准分别保存契约、专业指导和社区经验，并为社区经验增加适用条件与证据等级。

### 模型与业务知识耦合

旧资料包含即梦、Seedance、模型版本和历史命令。这些可以作为经验来源保留，但不能决定 Wsstudio 的实际模型或付费执行方式。

### 固定五秒与固定负面模板

多个旧 Skill 将每五秒一镜、统一时间段或固定负面约束写成默认结构。它们可能对某个 Skill 有价值，但不能成为所有 Skill 的核心模板。新契约只记录该 Skill 自己确认的时序策略。

## 对模板字段的影响

| 历史需求 | 新标准表达 |
|---|---|
| 图片1固定角色身份 | `role: identity` |
| 图片2及以后为有序场景 | 一个 `scene` 槽，`ordered: true`，`max_count: null` |
| 严格起始帧或结束帧 | 独立 `start_frame` / `end_frame` 槽 |
| 参考视频 | `media_type: video`, `role: footage` |
| 音乐驱动 | `media_type: audio`, `role: music` |
| 不同时长对应不同素材 | 放入该 Skill 的创作参考或后续扩展契约，不由通用正则猜测 |
| 一镜到底或硬切 | `transition_strategy: skill_defined`，具体方法进入创作指南 |
| 社区稳定性经验 | `community-experience.md`，带条件和证据等级 |
| 失败与负面要求 | `failure-cases.md`，记录表现、原因和修复 |

## 不进入通用模板的内容

以下信息即使在多个旧 Skill 中出现，也不能升级为全库硬规则：

- 固定每五秒一个镜头；
- 固定硬切或固定一镜到底；
- 固定主体静止或固定摄影机运动；
- 固定 8K、UE5、电影航拍等视觉媒介；
- 固定负面约束段落；
- 固定城市、地产、建筑、IP 或 Logo 场景；
- 固定 Seedance 版本、分辨率或 provider。
