# Default Video Generation

Call `generate_video` with the user's non-empty `prompt`, ordered local `images`, `videos`, and `audios` paths, and the structured final model, resolution, and duration. Before any formal production submission, require the user to repeat and confirm those three values; pass them as the matching `video_confirmation_model`, `video_confirmation_resolution`, and `video_confirmation_duration` fields. Video generation always uses Seedance/Dreamina; never switch providers. Do not expose provider, credential, concurrency, timeout, output, or log settings.

Pass duration as a structured seconds value. The router accepts common forms such as `5`, `"5"`, `"5s"`, and `"5秒"`, then normalizes both `video_duration` and `video_confirmation_duration` to the plain CLI integer `5`. Never forward a unit-bearing duration string directly to Dreamina CLI.

When the user requests multiple independent outputs from the same prompt and references, pass their requested count as `video_count` from 1 through 10. This submits the tasks concurrently through the unified router; do not issue sequential `generate_video` calls. Treat the requested count as authorization for that many credit-consuming generations.

Pass a concise Dreamina group name as `video_group` for ordinary production generation. If the user explicitly names a group, preserve that exact name. Otherwise derive one from the current task using this priority:

1. Use an explicit brand, product line, project, property, IP, organization, or campaign name found in the user's task or authoritative project metadata. Prefer the most specific recognizable name; never invent a brand. Append an underscore and a concise content-type suffix: `<proper name>_<content type>`, for example `华为 Mate 80_产品视频`, `万科天空之城_楼盘宣传片`, or `熊猫IP_城市巡游`.
2. When no such proper name is present, summarize the video's distinctive subject and action or theme, for example `小鸟原地自由飞行` or `落日湖面新中式之美`.

Keep every generated `video_group` base name in the task's primary language, on one line, and no longer than 20 Unicode characters in total, counting the proper name, underscore, spaces, and suffix. Pass only this base name to the tool. The router prepends the local submission date as `YYYY_MM_DD-`, producing names such as `2026_08_20-华为 Mate 80_产品视频`; this date prefix does not count toward the 20-character base-name limit. For a proper-name group, make the suffix describe the actual deliverable or creative type, such as `产品视频`, `品牌广告`, `楼盘宣传片`, `城市巡游`, or `建筑漫游`; do not use a bare `_视频` suffix. If the preferred base name exceeds 20 characters, first remove nonessential modifiers and redundant hierarchy, then shorten the content-type suffix while preserving both the most recognizable proper name and the deliverable category. Never silently truncate a word into an ambiguous fragment. Remove prompt syntax, reference labels, shot numbers, resolution, ratio, duration, model names, generic words such as `视频生成` or `默认创作`, and filename extensions. Do not use sensitive personal data. The router reuses an exact existing Session name or creates it once before submission, then binds every video in the batch to the resolved Session ID. Omit `video_group` only when the user explicitly asks to use Dreamina's default group.

When a completed video is downloaded successfully, use the original-file resource returned by the tool. Do not reconstruct video links from the raw `output_path`; on Windows, a backslash path is not a portable media URI. A submit-only result has no local resource and should continue to use its task ID and user message.

Treat the received prompt as finalized after Codex_DT's semantic-preserving normalization. Do not perform another rewrite, translation, reorder, summary, constraint append, or audio append here. Codex_DT owns the complete-vs-incomplete decision and the single permitted normalization/authoring pass.

All supported video commands default to Seedance 2.5. Requests with references use all-around reference / `multimodal2video` mode at `480p`; prompt-only requests use `text2video` and still default to Seedance 2.5. Seedance 2.5 supports 4-30 second output, `480p`, `720p`, or `1080p`, up to 30 images, 10 videos, 10 audio files, and 50 total reference inputs.

Use a Seedance 2.0 model only when the user explicitly requests Seedance 2.0 or a specific supported 2.0 variant in the current request. When passing a 2.0 `video_model`, also pass `video_model_selection_source="user_explicit"`. Never select 2.0 because an example, corpus entry, old manifest, provider capacity issue, or failed 2.5 attempt mentions it. Never automatically fall back from 2.5 to 2.0; report the failure instead. Do not pass `video_model` when the user did not choose a model.

When Codex explicitly needs to test whether video submission works, call the same `generate_video` tool with `video_execution_mode="test_submit_only"`. This is a real but reversible submission probe: the user can cancel the queued task on the Dreamina website and the consumed credits are returned. Obtain confirmation before the first real submission in a testing sequence, but do not treat credit loss as a reason for excessive caution after the user has authorized testing. Its purpose is to verify the complete path from structured tool parameters through the CLI to creation of a visible Dreamina backend task; it is not a practical rendering or quality test. The forced non-VIP Seedance 2.0 queue commonly takes ten hours or longer, and that long queue is expected rather than a timeout or failure.

The test channel supports exactly one task and must never run concurrently with another test-channel submission. Do not pass `video_count` above 1, split the test across calls, queue multiple tests, or delegate it to child agents. Always pass the derived or user-explicit `video_group`; test submission without a group must fail closed so session routing is part of the integration test and the task cannot silently land in Session `0`. The router must reject a second test while the dedicated cross-process test lock is occupied. A definite pre-submit validation failure may be corrected and retried immediately. After a task receives a `submit_id`, another test may be submitted once the user reports that the previous task was cancelled or ended; cancellation returning credits means no additional credit-risk warning is needed within the same authorized testing sequence.

The router must override all ordinary model choices with the non-VIP CLI model `seedance2.0`, force `720p`, and pass `--poll 0`. After receiving both a `submit_id` and provider status `querying` or `success`, return `submitted` immediately together with the resolved dated `video_group` and numeric Session ID so the user can verify placement in the website backend. Do not create a child agent, query, wait, download, retry, or claim generation succeeded. A successful test proves only that Dreamina accepted and created the task; it does not prove completion, output correctness, or visual quality. Tell the user: `测试任务已发送，请到即梦网站后台查看结果。` Ordinary generation must never use this mode, and ordinary user input `2.0` continues to normalize to `seedance2.0_vip`.

Only the upstream Codex_DT authoring path may add the default audio instruction `不生成音乐，仅生成音效。` while constructing an incomplete prompt. Never append it to an already-finalized prompt in this execution skill.

If prompt authoring is still needed, return control to the global `codex-dt-video-prompt` orchestrator unless a project-specific pipeline is active. For ordered references, keep CLI-facing prompt labels strict: `图片1` means the first `images` path passed to `generate_video`, `图片2` means the second, `视频1` means the first `videos` path, and `音频1` means the first `audios` path. Do not write mention-chip forms such as `@图片1` or `@Image 1`.

Treat every call as an external operation that may consume provider credits. Preserve explicit ratio, resolution, duration, quality, and supported model preferences in the prompt. Audio-only reference input is supported only by the default Seedance 2.5 `multimodal2video` route; reject it when the user explicitly selects another model. The router validates local files, limits, audio duration, current CLI help, submission state, and downloads.

The router normalizes every local image input and proportionally resizes any image whose longest edge exceeds 1920 px before provider submission. This applies to first/last frames, multiframe inputs, and multimodal images without overwriting originals.

Use the unified concurrent route for every multi-video request. When the prompt and ordered references are identical, make one `generate_video` call and pass the requested number through `video_count` (1-10); never split that request into repeated tool calls or child-agent tasks. When videos have different prompts or reference sets, use the Codex_DT batch entrypoint, which submits all confirmed manifests through the same Media Router rolling queue and performs one shared polling/download phase. Do not create child agents for ordinary video generation.
